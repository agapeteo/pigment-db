## Pressure analysis

- Across all 66 samples, throughput versus normalized CPU pressure has Pearson correlation `-0.948` and Spearman correlation `-0.930`.
- Across 33 pairs, the throughput ratio versus candidate-minus-baseline normalized CPU pressure has Pearson correlation `-0.887` and Spearman correlation `-0.917`.
- The direction reverses when the baseline receives more CPU pressure: multiple pairs strongly favor the candidate, reaching ratios above `1.6`.
- I/O pressure does not show the same negative relationship, so CPU service or runnable contention is the primary observed confounder.

These relationships are too strong to ignore, but global PSI can include both outside workload and contention generated by the benchmark itself. It therefore cannot distinguish scheduler interference from candidate-specific extra CPU work.

## Recommendation

Do not weaken SC-005 and do not optimize production code blindly. Prepare one final focused diagnostic that adds safe per-worker `/proc/thread-self/stat` CPU-tick deltas and voluntary/involuntary context-switch counts around each sample while retaining the longer matrix. This will separate extra CPU work from lost wall-clock service:

- Similar CPU ticks per operation with worse wall time and more involuntary scheduling supports an environment/protocol remediation.
- Higher candidate CPU ticks per operation supports profiling and optimizing the V2 write path before another acceptance run.

After that classification, request explicit approval for the applicable remediation and then run a fresh complete SC-005 capture.
